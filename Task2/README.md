# Определение доменов

Система разделена на четыре предметных домена, каждый из которых соответствует самостоятельной бизнес-способности компании. Границы доменов проведены так, чтобы:

- Каждый домен владел своими операционными данными и логикой.
- Взаимодействие между доменами происходило через асинхронные события и чёткие API.
- Домены могли развиваться независимо, без внесения изменений в центральное DWH.

| Домен                  | Владелец данных                       | Основные сущности                                                                                                             | Ответственность                                                                                                                                      |
|------------------------|---------------------------------------|-------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------|
| Клиники                | Подразделение клиник                  | Пациенты, медицинские карты (EHR), история болезней, снимки, инвентарь, персонал, расписание                                  | Управление медицинской деятельностью, операционные процессы. EHR строго изолированы и не передаются в аналитическую витрину.                         |
| Финтех                 | Финтех-компания (банк)                | Клиентские счета, кредиты, платежи, финансовые транзакции, выписки                                                            | Банковские операции, кредитный скоринг, обработка платежей. Все финансовые данные защищены банковской тайной.                                        |
| ИИ-сервисы             | Компания по разработке AI             | Модели машинного обучения, результаты анализа медицинских данных (диагнозы, предсказания), агрегированные медицинские метрики | Обработка медицинских данных (изображения, тексты) для поддержки врачебных решений. На выходе даёт структурированные результаты (без исходных карт). |
| Интеграция и партнёры  | Головной офис / архитектурный комитет | API-шлюзы, события для внешних партнёров (фармацевтика, производители электроники), нормализованные данные для обмена         | Обеспечение безопасного двустороннего обмена данными с внешними организациями. Адаптация протоколов и форматов без изменения внутренних доменов.     |

Кроме того, существует общая платформа данных, которая не является самостоятельным доменом, а предоставляет инфраструктурные сервисы:

- Data Lakehouse – централизованное хранилище сырых событий от всех доменов (с соблюдением правил доступа).
- Семантический слой – унифицированное представление бизнес-метрик для отчётности (строится над витринами).
- Портал самообслуживания – потребительский интерфейс для построения отчётов (использует семантический слой).


# Data Flow Diagram (DFD) – потоки данных между доменами

Пояснение к диаграмме:

- Все изменения состояния в любом домене публикуются как события в шину событий (Kafka). Это обеспечивает асинхронную связь и слабую связанность.
- Data Lakehouse потребляет все события и сохраняет их в трёх уровнях (Bronze – сырые, Silver – очищенные, Gold – агрегированные витрины). Витрины создаются отдельно для каждого домена, что позволяет каждому домену строить свою аналитику независимо.
- Семантический слой – это надстройка над витринами, которая предоставляет унифицированные бизнес-показатели (KPI) для портала самообслуживания. Здесь же реализуется управление доступом на уровне строк (RLS) для соблюдения регуляторных требований.
- Прямые синхронные вызовы допускаются только для критических операций (например, получение финансовой информации для проверки оплаты в клинике), но они минимизированы.
- Домен интеграции выступает как шлюз для внешних партнёров: принимает их данные, конвертирует во внутренние события и публикует в шину, а также подписывается на события, которые должны быть переданы партнёрам (с обезличиванием и агрегацией при необходимости).

## Поддержка ключевых бизнес-сценариев через потоки данных

| Бизнес-сценарий                                 | Как обеспечивается потоками данных                                                                                                                                                                                                                                                                |
|-------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Быстрая подготовка отчётности                   | Все домены публикуют события → Data Lake → витрины Gold → семантический слой. Портал самообслуживания читает только готовые агрегаты, поэтому отчёты строятся за секунды, а не часы.                                                                                                              |
| Интеграция нового финтех-сервиса                | Новый сервис подключается к шине событий: публикует свои события и подписывается на нужные (например, данные о клиентах). Ему не нужно править DWH – он сам строит свою витрину в Data Lake.                                                                                                      |
| Использование ИИ для анализа медицинских данных | Клиники публикуют событие "исследование выполнено" с ссылкой на изображение (само изображение хранится отдельно в защищённом хранилище). ИИ-сервис подписывается, загружает изображение, обрабатывает и публикует результат. Данные для аналитики (агрегированные метрики) попадают в витрину ИИ. |
| Подключение производителя электроники           | Производитель обменивается данными о поставках через домен интеграции. Его события (складские остатки, заказы) публикуются в шину, и домен "Клиники" может подписаться на них для планирования инвентаризации. Всё это без изменения центрального DWH.                                            |
| Развитие каждого направления независимо         | Каждый домен имеет собственный стек технологий (Golang/Java для финтеха, Python для ИИ, .NET для клиник). Изменения в одном домене не затрагивают другие, так как интерфейсом служат только события и контракты API.                                                                              |

# Аргументация разделения на домены и преимущества для бизнеса

| Преимущество                                             | Пояснение                                                                                                                                                                                                                                                                 |
|----------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Ускорение вывода продуктов (Time-to-Market)              | Команды доменов автономны: они могут выпускать новые фичи без согласования с другими отделами и без перетестирования всего DWH. Например, финтех может запустить новый кредитный продукт, просто добавив новые поля в свои события и витрину – клиники и ИИ не затронуты. |
| Снижение зависимости от монолитного DWH                  | Бизнес-логика вынесена из хранилища в доменные сервисы. DWH (теперь Data Lake) служит лишь хранилищем сырых фактов, а не местом реализации логики. Это позволяет легко менять источники или форматы данных без простоев.                                                  |
| Независимое развитие направлений                         | Каждый домен выбирает свои инструменты, языки и темпы релизов. ИИ может обновлять модели еженедельно, финтех – соблюдать банковские релизные циклы, клиники – фокусироваться на надёжности. Конфликты ресурсов и кода исключены.                                          |
| Масштабируемость и отказоустойчивость                    | Асинхронная шина событий позволяет масштабировать каждый компонент по нагрузке независимо. При сбое в одном домене остальные продолжают работать, так как события буферизируются.                                                                                         |
| Безопасность и соответствие регуляторам                  | Медицинские EHR изолированы в домене клиник и не попадают в аналитические хранилища. Финансовые данные также защищены на уровне домена. Разграничение доступа реализуется на уровне событий и витрин, что упрощает аудит.                                                 |
| Простота подключения новых бизнесов (фарма, электроника) | Новый партнёр интегрируется через домен интеграции. Ему не нужно знать внутреннюю структуру DWH – достаточно публиковать/подписываться на стандартизированные события. Это сокращает время интеграции с месяцев до недель.                                                |
